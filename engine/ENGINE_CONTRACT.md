# Gatekeeper engine contract

This is the handoff document for the FastAPI/MCP teammate. The engine is synchronous, deterministic, and contains no LLM, HTTP server, prompt handling, or post-check. It never lets a model write Cypher or choose a verdict.

## Public entry point

```python
from gatekeeper_engine import Gatekeeper

engine = Gatekeeper.from_env()
```

`Gatekeeper.from_env()` reads `FALKORDB_HOST`, `FALKORDB_PORT`, `FALKORDB_USERNAME`, `FALKORDB_PASSWORD`, `FALKORDB_GRAPH`, and optional `FALKORDB_MAX_CONNECTIONS`. Defaults are `127.0.0.1`, `6379`, and `gatekeeper`.

The client is pooled and shared; each method selects a fresh Graph wrapper. A concurrency test with 8 workers / 24 checks passed on FalkorDB v4.22.1 and `falkordb` 1.8.0. Serialize multi-query reversal writes in the HTTP layer if concurrent writes are possible.

## Result rules

- Every check, why, reverse, who, affected, and audit finding carries an evidence `path`.
- `PathEdge.provenance` is `REAL`, `CURATED`, or `SYNTHETIC`; missing stored values default to `SYNTHETIC`.
- `Source.title` is optional in storage and falls back to the source id in the response.
- `Answer` nodes carry `target`, `action`, and `verdict` in addition to the base schema so reverse dry-run can be graph/ledger aware.
- A viewer is `MERGE`d into `Person`. The default `anonymous` handle is a real graph node once a public `check()` is called.

## Verdict semantics

Order is fixed:

1. unresolved target → `UNKNOWN_TARGET`
2. live high-severity `prohibits` → `BLOCK`
3. live `prohibits` or `requires_approval` → `ESCALATE`
4. live governing rule with a dead premise → `STALE`
5. only dead or informational governance → `ALLOW`
6. no governing decision for the action → `UNGOVERNED`

Dead premises are not safe. `UNGOVERNED` is not safe. Shallow depth is intentionally incomplete.

## Validation and errors

`ValidationError` is a typed `ValueError` with `.code` and `.message`.

- `INVALID_ACTION`
- `INVALID_DEPTH`
- `INVALID_VIEWER`
- `INVALID_TARGET_NAME`
- `UNKNOWN_TARGET_NAME`
- `INVALID_DECISION_NAME`
- `UNKNOWN_DECISION_NAME`
- `INVALID_REVERSAL`
- `INVALID_LIMIT`
- `INVALID_OVERRIDES`

Action/depth validation runs before any database query. `resolve_target()` and decision-specific methods raise `UNKNOWN_*`; `check()` preserves the product's `UNKNOWN_TARGET` verdict so a checkpoint can explain the miss.

## Dry-run reversal

`reverse(..., dry_run=True)` does not write. It queries dependent decisions and all inherited artifact/action governance pairs, runs the current check and an override check treating the old id as superseded, and returns:

```json
{
  "flips": [{
    "target": "file:compat/win7_shim.js",
    "action": "delete",
    "decision": "D2",
    "from_verdict": "ESCALATE",
    "to_verdict": "STALE",
    "path": {"nodes": [], "edges": []}
  }],
  "affected_people": [],
  "committed": false,
  "path": {"nodes": [], "edges": []}
}
```

The empty `affected_people` in this example is intentional for the no-ledger case; the real seeded example contains Alice and Carol.

## Not in this engine

- FastAPI routes, authentication, HTTP serialization, MCP, agent tool selection, LLM explanation, and post-check name verification.
- Data ingestion or a real/curated corpus.
- Enforcement. Gatekeeper is advisory and only knows recorded graph state.
